From Words to Numbers
Before any model can process language, words must become numbers. Here's how that works.

Why machines need numbers

Neural networks — including transformers — are fundamentally mathematical functions. They can only operate on numbers, not letters or words. The first job is converting text into a numerical form the model can process.

Step 1 — Tokenization

Tokenization splits raw text into small chunks called tokens. A token is not always a full word — it might be a word, a sub-word fragment, or a character, depending on the tokenizer.

Most modern LLMs use Byte-Pair Encoding (BPE). BPE starts with individual characters and repeatedly merges the most common adjacent pairs into new tokens until it reaches a target vocabulary size (typically 50,000–100,000 tokens).

Examples of how BPE tokenizes text:

  • "unhappiness" → ["un", "happi", "ness"]
  • "transformer" → ["transform", "er"]
  • "ChatGPT" → ["Chat", "G", "PT"]
  • "hello world" → ["hello", " world"]

Each token is assigned an integer ID. "hello" might be token 15496. The model only ever sees these integers — never raw text.

Step 2 — Embeddings

An integer ID like 15496 doesn't carry any meaning on its own. The model converts each token ID into a dense vector — a list of hundreds or thousands of floating-point numbers. This is an embedding.

Embeddings are learned during training. The model adjusts these vectors so that words used in similar contexts end up with similar vectors. Two words are "similar" if their vectors are close — measured by the angle between them (cosine similarity).

This creates a geometric space of meaning:

  • "dog" and "cat" end up near each other
  • "Paris" ends up near "France", "London", "England"
  • The vector offset king − man points in roughly the same direction as queen − woman

Embeddings are the model's learned dictionary of meaning. GPT-4 uses 12,288-dimensional embeddings — each token becomes a vector with 12,288 numbers that together encode its meaning in context.

Lesson 2 of 5
Self-Attention
The core innovation of transformers — letting every token look at every other token to understand context.

The context problem

The word "bank" means completely different things in these two sentences:

  • "I deposited money at the bank."
  • "The otter swam to the river bank."

A model that looks at each word in isolation can't tell the difference. It needs to understand the surrounding context to interpret any given word. This is what self-attention solves.

What self-attention does

Self-attention lets every token in a sequence look at every other token and decide how much to "pay attention" to each one. The result is a new, context-aware representation for each token — the word "bank" now knows from context whether it's near "river" or "money" and updates its meaning accordingly.

Query, Key, Value (Q, K, V)

Each token produces three vectors:

  • Query (Q) — "What information am I looking for?"
  • Key (K) — "What information do I contain?"
  • Value (V) — "What do I actually pass forward if someone attends to me?"

The attention score between token A (query) and token B (key) is the dot product Q_A · K_B, divided by √d to keep numbers stable. Applying softmax to all scores gives weights that sum to 1 — a probability distribution over which tokens to attend to.

The final output for a token is the weighted sum of all Value vectors. If "it" attends 80% to "animal" and 10% to "street", its new representation is 80% the value of "animal" plus 10% the value of "street" — it literally absorbs meaning from those tokens.

Self-attention is O(n²) in the sequence length — every token attends to every other. This is why longer context windows are expensive: 2× the tokens = 4× the attention computation.

Lesson 3 of 5
The Transformer Block
Self-attention is just one piece. Here's the full block that gets stacked to build GPT and BERT.

Multi-head attention

Instead of running self-attention once, transformers run it N times in parallel with different learned weight matrices. Each "head" learns to notice different kinds of relationships:

  • One head might learn syntactic structure (subject → verb)
  • Another might learn coreference ("it" → "animal")
  • Another might learn positional relationships

The N heads' outputs are concatenated and projected back to the model's dimension. This gives the model multiple simultaneous "perspectives" on the same sequence.

Residual connections

After attention, the original input is added back to the attention output: output = attention(x) + x. This is called a residual connection.

Why? Deep networks are hard to train — gradients vanish. By adding the input back, you ensure there's always a direct path for gradients to flow backward. The attention only needs to learn the change, not the full transformation.

Layer normalisation

After the residual add, the values are normalised across the feature dimension. This keeps activations in a stable range, preventing exploding or vanishing numbers as the signal passes through many layers.

Feed-forward network

After attention, each token's representation is passed through a small two-layer MLP independently. This is where the model does per-token "thinking" — storing factual knowledge and refining the representation. The hidden dimension is typically 4× wider than the embedding dimension.

Stacking blocks

One block = Multi-Head Attention + Add&Norm + Feed-Forward + Add&Norm. GPT-2 stacks 12 blocks. GPT-3 stacks 96. Each block builds a progressively more abstract representation — early blocks handle syntax, later blocks handle semantics and facts.

BERT vs GPT — Encoder vs Decoder
Same transformer blocks, but one crucial difference in how tokens are allowed to attend to each other.

Two ways to use the transformer block

The transformer architecture was originally designed with an encoder (reads the input) and a decoder (generates the output), like in translation. Later research found that using just one half works extremely well for different tasks.

Encoder-only: BERT

In an encoder, every token can attend to every other token — both before and after it. This is called bidirectional attention. The model sees the full sentence at once and builds rich contextual representations.

Best for tasks where you need to understand text:

  • Sentiment classification — is this review positive or negative?
  • Named Entity Recognition — find all person/place/org names
  • Semantic search — embed a sentence into a vector for retrieval
  • Question answering — find the answer span in a passage

Decoder-only: GPT

In a decoder, each token can only attend to tokens that came before it — never future tokens. This is enforced with a causal mask: a triangular mask that blocks attention to the future. The model only knows what has been generated so far.

Why? Because at generation time, future tokens literally don't exist yet. You can't "cheat" by looking at the answer when generating it. This also makes generation possible: produce one token, append it, produce the next, repeat.

Best for tasks where you need to generate text:

  • Text completion and chat (GPT-4, Claude)
  • Code generation (GitHub Copilot)
  • Summarisation, translation (with a prompt)

Encoder-decoder: T5, BART

The original full transformer: encoder reads the input with full bidirectional attention; decoder generates output attending to its past tokens plus cross-attends to the full encoder output. Used for translation, summarisation with separate input/output sequences.

The practical upshot for AI engineering: use BERT-family models for embeddings and classification. Use GPT-family models (including Claude) for generation. Use T5/BART for structured input→output mappings.

Practical Transformers
Context windows, memory costs, scaling laws — everything you need to reason about LLMs as an engineer.

Why context windows are limited

Self-attention is O(n²) in sequence length — every token attends to every other. Double the context, and attention cost quadruples. This is a hard computational constraint:

  • 1,024 tokens → 1× cost
  • 2,048 tokens → 4× cost
  • 8,192 tokens → 64× cost
  • 32,768 tokens → 1,024× cost

Modern techniques (Flash Attention, RoPE, sliding window attention) reduce this in practice, but the fundamental constraint remains: long contexts are expensive.

The KV cache

During generation, the model already computed Key and Value vectors for all past tokens. Recalculating them every step would be O(n) work per token. Instead, the model caches past K and V tensors and reuses them — only computing attention for the new token.

This is why generating 1,000 tokens from a 100,000-token context is feasible — the KV cache pays the per-token cost once. The downside: the KV cache lives in VRAM, so very long contexts consume enormous GPU memory.

How much memory does a model need?

Model parameters are stored as floating-point numbers. In fp16 (half precision, standard for inference), each parameter takes 2 bytes:

  • 7B parameters × 2 bytes = 14 GB VRAM minimum
  • 13B parameters × 2 bytes = 26 GB VRAM
  • 70B parameters × 2 bytes = 140 GB VRAM (needs multiple GPUs)
  • 405B parameters × 2 bytes = 810 GB VRAM

Add the KV cache and activations on top. This is why running large models locally requires serious hardware.

Scaling laws

Kaplan et al. (2020) found that model capability improves predictably as you scale up three things: model parameters, training data, and compute. The improvement is log-linear — each doubling of scale gives a roughly constant improvement on benchmarks. This is why labs keep building bigger models.

How this connects to Phase 0

Everything you learned in Phase 0 directly applies here: GPU tensor cores compute the matrix multiplications inside every attention head. VRAM holds the model weights and KV cache. The cache hierarchy (L1/L2/L3/RAM) speeds up loading attention weights. Distributed computing (Spark, NVLink) spreads large models across multiple GPUs.
