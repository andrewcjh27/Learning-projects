Lesson 01
Generators & Iterators
Lazy evaluation with yield — produce values on demand and process datasets that don't fit in memory.

What is a generator?

A generator is a function that uses yield instead of return. Each call to next() resumes execution until the next yield, then pauses again. The function body does not run until you iterate over the generator.

Lazy evaluation

Regular list comprehensions build the entire list in memory at once. A generator expression (x*2 for x in range(1_000_000)) produces items one at a time, holding only the current value in memory — roughly 100 bytes vs 8 MB for a list of 1M integers.

  • yield — turns a function into a generator factory
  • next(gen) — advance by one item
  • for x in gen — consume all items lazily
  • (expr for x in iterable) — generator expression

itertools

The itertools module provides lazy combinators that work on any iterable without materialising intermediate results.

  • itertools.chain(a, b) — concatenate iterables
  • itertools.islice(gen, n) — take first n items
  • itertools.groupby(data, key) — group consecutive runs

For large CSV files or database cursors, generators let you process rows one at a time — you never need to load the full dataset into RAM.

Why doesn't yield hold onto the row?

yield doesn't delete the row — Python's reference counting does. When the loop variable row is rebound to the next item, nothing points to the old row anymore, so its memory is freed automatically.

Compare what's alive in memory during each loop iteration:

List — all rows live simultaneously 
rows = [process(r) for r in file]
# ☠ 10M objects in RAM right now
for row in rows:
    save(row)
# list still holds every reference
Generator — one row at a time 
rows = (process(r) for r in file)
# nothing runs yet — just a promise
for row in rows:
    save(row)
# row 1 freed before row 2 exists

The generator pauses after each yield. The next item isn't produced until the loop asks for it — at which point the previous item has already been handed off and can be collected.

Lesson 02
Type Hints & Pydantic
Annotate your code, validate data at the boundary, and catch bugs before they reach production.

Python type hints

Type hints (PEP 484) are annotations that tell readers — and tools — what types a function expects and returns. Python itself doesn't enforce them at runtime, but mypy does static analysis.

  • def process(data: list[dict]) -> pd.DataFrame
  • Optional[str] — either str or None
  • Union[int, str] — one of several types
  • TypeVar('T') — generic type parameter

Pydantic

Pydantic enforces type hints at runtime. Define a model class inheriting from BaseModel; Pydantic validates and coerces data on instantiation, raising a ValidationError with field-level messages when something is wrong.

  • model.model_dump() — serialise to dict
  • Coercion: "42" becomes 42 for an int field
  • Strict types, custom validators, nested models

Validate data at the entry point of your pipeline. A ValidationError on row 1 is infinitely better than a silent wrong answer on row 1 000 000.

Lesson 03
Polars vs Pandas
Why a Rust-backed columnar dataframe library can be 10–100× faster than Pandas for production workloads.

Why Pandas can be slow

Pandas stores data as Python objects row-by-row internally for mixed types. Operations loop through Python objects, which means interpreter overhead on every row. It is single-threaded and eager by default.

What Polars does differently

Polars is written in Rust and uses the Apache Arrow columnar memory format. Operations vectorise over contiguous typed arrays, run in parallel across CPU cores by default, and the lazy API (pl.scan_csv().filter().collect()) builds a query plan that Polars optimises before executing.

  • Columnar storage — SIMD-friendly, cache-efficient
  • Parallel execution with no extra configuration
  • Lazy evaluation — query optimiser rewrites your plan
  • Zero-copy interop with PyArrow and NumPy

Use Pandas for interactive exploration and small datasets. Switch to Polars for anything that takes more than a few seconds or processes files larger than a few hundred MB.

Lesson 04

    
Async & Concurrency

    
Single-threaded cooperative multitasking with asyncio — the right tool for I/O-bound workloads.

  


  

    

      
The GIL recap

      
The Global Interpreter Lock means only one Python thread runs bytecode at a time. Threads help with I/O-bound work (the GIL is released during I/O) but not CPU-bound work.

      
asyncio event loop

      
asyncio is single-threaded cooperative multitasking. An async def function is a coroutine — it runs until it hits an await, at which point control returns to the event loop so another coroutine can progress.

      
    
        
  • async def fetch(url) — define a coroutine
    • 
        
  • await response.json() — yield control until done
    • 
        
  • asyncio.gather(*tasks) — run many coroutines concurrently
    • 
        
  • aiohttp — async HTTP client built on asyncio
    • 
      

      
When async helps

      
Async shines when you have many I/O-bound tasks: hundreds of HTTP requests, database queries, file reads. For CPU-bound work use multiprocessing or ProcessPoolExecutor.

      
Never call a blocking function (requests.get, time.sleep) inside a coroutine — it blocks the entire event loop. Use asyncio.sleep and aiohttp instead.

async def
Defines a coroutine — returns a coroutine object, doesn't run immediately

    
await

Decorators & Functools

    
Wrap functions to add logging, caching, retry logic, and more — without changing the function body.

  


  

    

      
What is a decorator?

      
A decorator is a function that takes a function and returns a new function. The @decorator syntax is shorthand for fn = decorator(fn). Use functools.wraps inside your decorator to preserve the original function's __name__ and __doc__.

      
functools highlights

      
    
        
  • @functools.lru_cache(maxsize=128) — memoises calls, keyed by args
    • 
        
  • @functools.cache — unbounded memoisation (Python 3.9+)
    • 
        
  • functools.partial(fn, arg) — pre-fill arguments to create new callables
    • 
        
  • @dataclass — auto-generate __init__, __repr__, __eq__
    • 
      

      
Real-world patterns

      
    
        
  • @timer — log execution time of expensive functions
    • 
        
  • @retry(n=3) — retry failed HTTP requests automatically
    • 
        
  • @rate_limit — enforce API rate limits transparently
    • 
        
  • @lru_cache — eliminate redundant DB or API calls
    • 
      

      
Memoisation turns an exponential-time recursive Fibonacci into linear time. For fib(10), the naive version makes 177 calls; with @lru_cache it makes just 11.
