Lesson 01
The Shell
How your commands become system calls, and the pipes and redirects that let you chain tools together.

What is a shell?

A shell is a program that reads your text commands and asks the OS kernel to execute them. bash and zsh are both shells — they differ in features but share 95% of syntax. The terminal is just the window that hosts the shell.

stdin, stdout, stderr

Every Unix process has three data streams: stdin (0) for input, stdout (1) for normal output, stderr (2) for error messages. By default all three connect to your terminal, but you can redirect them anywhere.

Pipes and redirects

  • cmd1 | cmd2 — stdout of cmd1 becomes stdin of cmd2
  • cmd > file.txt — overwrite file with stdout
  • cmd >> file.txt — append stdout to file
  • cmd 2> err.log — redirect stderr to file
  • cmd 2>&1 — merge stderr into stdout

Pipes are the Unix philosophy in action: small programs that do one thing well, chained together. cat access.log | grep "404" | sort | uniq -c | sort -rn | head -10 finds your top 404-producing URLs — no custom code needed.

Lesson 02
Shell Scripts
Automate repetitive tasks by writing bash scripts — variables, loops, conditionals, and functions.

Shebang and variables

The first line #!/bin/bash tells the OS which interpreter to use. Variables are set with NAME="Alice" (no spaces around =) and read with $NAME or ${NAME}. Positional arguments arrive as $1, $2, etc.; $# is the count, $@ is all args.

Command substitution

Capture a command's output into a variable: DATE=$(date +%Y-%m-%d) or older syntax `date`. You can use this inline: echo "Today is $(date +%A)".

Conditionals

if [ condition ]; then … elif …; else …; fi. Common tests: -f file (file exists), -d dir (is directory), -z "$var" (empty string), -eq / -lt / -gt for numbers, == / != for strings.

Loops

  • for f in *.log; do echo "$f"; done
  • for i in $(seq 1 10); do …; done
  • while read line; do echo "$line"; done < file.txt

Exit codes

$? holds the exit code of the last command (0 = success, non-zero = failure). Add set -e at the top of a script to abort on any error — a safety net for automation.

Always quote variables: "$var" not $var. Unquoted variables break when they contain spaces, which causes subtle bugs that only appear in production.

Lesson 03
SSH & tmux
Connect to remote servers securely and keep your work alive even when your connection drops.

SSH — Secure Shell

SSH creates an encrypted tunnel between your machine and a remote server. ssh user@host connects interactively. The first connection asks you to verify the server's fingerprint — say yes, and it's saved in ~/.ssh/known_hosts.

Key-based authentication

Passwords over SSH are weak. Key pairs are better: ssh-keygen -t ed25519 -C "you@email" creates a private key (~/.ssh/id_ed25519) and a public key (.pub). Copy the public key to the server with ssh-copy-id user@host — it lands in the server's ~/.ssh/authorized_keys.

~/.ssh/config

Stop typing long hostnames. Add an alias:

Host prod
  HostName 12.34.56.78
  User ubuntu
  IdentityFile ~/.ssh/id_ed25519

Now ssh prod is all you need. scp file.txt prod:/tmp/ copies files.

tmux — Terminal Multiplexer

tmux runs sessions on the server that outlive your SSH connection. Disconnect, reconnect, reattach — your processes keep running. One session can hold multiple windows (like browser tabs) each split into panes.

  • tmux new -s work — create named session
  • Ctrl+b d — detach (session stays alive)
  • tmux attach -t work — reattach
  • Ctrl+b % — split pane vertically
  • Ctrl+b " — split pane horizontally
  • Ctrl+b → — move between panes
  • Ctrl+b c — new window, Ctrl+b n next

Lesson 04
Git
Track every change, branch without risk, and collaborate through pull requests — the version control system used by virtually all software teams.

Three areas

Git tracks files across three areas: the working directory (your actual files), the staging area / index (changes you've selected for the next commit), and the repository (permanent snapshot history). git add moves changes to staging; git commit saves staging to the repository.

Branches

A branch is just a pointer to a commit. Create one with git checkout -b feature/login (or git switch -c). Work on your branch independently — main stays clean. Merge back with git merge feature/login or rebase with git rebase main for a linear history.

Remote workflow

  • git remote add origin URL — link to GitHub
  • git push -u origin main — push + set upstream
  • git pull — fetch + merge remote changes
  • git fetch — download without merging
  • git stash — temporarily shelve uncommitted changes

Good commit messages

Use the imperative mood ("Add login page", not "Added"). Keep the subject under 72 chars. Explain the why not the what — the diff shows what changed, the message should say why.

.gitignore lists patterns to never track: __pycache__/, .env, *.pyc, node_modules/. Commit it early — cleaning up accidentally-tracked secrets is painful.

Lesson 05
Cron & Automation
Schedule scripts to run automatically — daily backups, hourly reports, recurring cleanups.

What is cron?

The cron daemon is a background process that wakes up every minute and runs any scheduled jobs whose time has come. You manage your jobs with crontab -e (edit) and crontab -l (list).

The five fields

Each cron line: minute hour day month weekday command

  • minute — 0–59
  • hour — 0–23
  • day of month — 1–31
  • month — 1–12
  • weekday — 0–6 (Sunday = 0 or 7)

Special values: * = every, */5 = every 5, 1-5 = range Mon–Fri, 1,3,5 = specific values.

Common patterns

  • 0 * * * * — every hour on the hour
  • 0 0 * * * — daily at midnight
  • 0 9 * * 1-5 — weekdays at 9 am
  • */15 * * * * — every 15 minutes
  • @reboot command — run once at system start

Logging output

Cron jobs have no terminal by default — always redirect output: 0 0 * * * /scripts/backup.sh >> /var/log/backup.log 2>&1. The 2>&1 merges stderr into stdout so errors are captured too.

Set the MAILTO="" variable at the top of your crontab to suppress the default email-on-output behaviour, which can flood your system mailbox.
