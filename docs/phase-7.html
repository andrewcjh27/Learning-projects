Lesson 01 / 05
Core Services: EC2 & S3
Virtual machines in the cloud and durable object storage — the foundation of most AWS architectures.

EC2 — Elastic Compute Cloud

EC2 gives you virtual machines (instances) in the cloud. You choose the instance type based on your workload's CPU, RAM, and network needs.

  • t3 (burstable) — cheap, earns CPU credits at low use, ideal for dev/staging
  • m6i (general purpose) — balanced CPU/RAM for most web workloads
  • c6i (compute-optimised) — high CPU:RAM ratio, for batch/encoding
  • r6i (memory-optimised) — high RAM, for in-memory databases
  • p3 (GPU) — NVIDIA V100 GPUs for ML training

EC2 Pricing Models

  • On-Demand — pay by the hour/second, no commitment, most expensive
  • Reserved (1–3yr) — commit upfront, save 40–60%
  • Spot — spare AWS capacity, up to 90% off, can be interrupted

S3 — Simple Storage Service

Object storage with 11 nines (99.999999999%) durability. Objects are key-value pairs where the key is the full path.

  • Lifecycle policies — auto-archive to Glacier after N days
  • Presigned URLs — time-limited access to private objects
  • Storage classes — Standard, Intelligent-Tiering, Glacier, Glacier Deep Archive

Tip: Never use S3 as a database — it has no transactions. Use it for blobs, logs, and data lake raw files.

Lesson 02 / 05
IAM & Security
Identity and Access Management — controlling who can do what, the right way.

IAM Fundamentals

IAM controls authentication and authorisation for every AWS API call. Everything revolves around policies — JSON documents granting or denying actions.

  • Users — humans with long-lived credentials
  • Groups — collections of users sharing policies
  • Roles — assumed by services (EC2, Lambda) or federated users
  • Policies — Effect + Action + Resource + optional Condition

Principle of Least Privilege

Grant only the minimum permissions needed. Start with Deny * and allow explicitly rather than allowing * and hoping for the best.

Roles vs Users

  • IAM Role — no long-lived keys; EC2 → S3 access via instance profile
  • IAM User — for humans; rotate access keys regularly
  • STS — Security Token Service issues temporary credentials (15min–36hr)

Never hardcode AWS credentials in source code. Use IAM roles for services and environment variables / secrets managers for local dev.

Service Control Policies

SCPs apply at the AWS Organisation level — they act as guardrails that can't be overridden even by account admins.

Lesson 03 / 05
Lambda & Serverless
Run code without managing servers. Pay only for execution time.

What is Lambda?

AWS Lambda executes your function code in response to events. AWS manages all the infrastructure — you only write the handler.

  • Event sources: API Gateway, S3 events, SQS, SNS, EventBridge cron
  • Timeout: max 15 minutes per invocation
  • Memory: 128MB – 10GB (CPU scales proportionally)
  • Pricing: $0.20 per 1M requests + $0.0000166667 per GB-second

Cold Start vs Warm Start

A cold start occurs when Lambda must initialise a new execution environment (~100ms–1s). Subsequent invocations reuse the warm container (milliseconds).

  • Keep init code outside the handler to minimise cold start work
  • Use Provisioned Concurrency for latency-critical APIs

ECS Fargate

For containerised workloads that exceed Lambda's 15-minute timeout, use ECS Fargate — serverless containers, no EC2 to manage.

Common pattern: S3 file upload → Lambda triggered → transforms data → writes to DynamoDB or another S3 key. Extremely cost-effective for ETL.

Lesson 04 / 05
S3 + Athena Data Lake
Query petabytes of data on S3 with serverless SQL — and slash costs with smart partitioning.

The Data Lake Pattern

Raw data lands in S3. Athena queries it with SQL (powered by Presto under the hood) — no ETL pipeline required to start analysing.

  • Glue Data Catalog — stores table schemas (column names, types, partition keys)
  • Glue ETL — Spark-based jobs for heavy transformations
  • Athena pricing: $5 per TB scanned

Partitioning

Store data in a hierarchical key structure:
s3://bucket/events/year=2024/month=01/day=15/

Athena reads only partitions that match the WHERE clause — dramatically cutting bytes scanned and cost.

Columnar Formats

  • Parquet / ORC — columnar, compressed; Athena only reads needed columns
  • Combined effect: partitioning + Parquet can cut costs 100× vs raw JSON/CSV

Rule of thumb: always partition by the most common filter key (usually date), and convert raw JSON to Parquet in your first ETL step.

Lesson 05 / 05
Cost & Architecture Patterns
Well-Architected Framework, VPCs, Auto Scaling, and the hidden cost killers.

Well-Architected Framework

  • Reliability — Multi-AZ, Auto Scaling, health checks
  • Security — least privilege, encryption at rest & in transit
  • Cost Optimisation — right-sizing, Spot, Reserved
  • Performance — right instance type, caching layers
  • Sustainability — use managed services, avoid waste

Cost Killers to Watch

  • NAT Gateway — $45/mo + $0.045/GB data transfer
  • Unattached EBS volumes — still billed after instance termination
  • Over-provisioned RDS — use Aurora Serverless for variable workloads
  • Data egress — outbound internet transfer is charged; keep services in same region/AZ

Networking Basics

  • VPC — private virtual network; spans AZs
  • Security Groups — stateful firewall at the instance level
  • NACLs — stateless firewall at the subnet level
  • ALB — Application Load Balancer; terminates TLS, routes by path/host

Auto Scaling: scale-out on high CPU, scale-in on low — but set a cooldown period to avoid thrashing.
